# PET 다일자 기술 재현

이 기술 경로는 기존 R1 샘플 분석과 완료 ZIP을 보존하고, SIT-PET 1.1의 전체 PET·객체·신호 기록으로 조건부 기술통계를 확장한다. 공모전 보고서·정책 제안·발표자료를 생성하지 않는다. 원래 직진 진입 경계 분석은 `DEFERRED_OUT_OF_SCOPE`다.

## 입력과 범위

`configs/pet_multiday_finish.yaml`은 실제 다운로드한 ZIP 내부 루트 경로를 지정한다. PET, objects, signals는 Zenodo 고정 record 19231310의 전체 파일이다. scenarios 정의만 같은 버전 examples ZIP에서 재사용한다. auxiliary ZIP의 geofence는 취득·검사 기록으로 보존하지만 독립적인 궤적 기하학 검증에 사용했다고 주장하지 않는다. tracks는 다운로드하거나 파싱하지 않는다.

취득 근거는 `state/finish_20261013/acquisition/attempt_*.json`이다. 아카이브 취득 호출 4회가 모두 HTTP 200으로 성공했고 신규 전송량 129,821,999바이트, 앞선 R1 추가 메타데이터 9,972바이트를 포함한 누계 129,831,971바이트다. 원래 예제 ZIP 150,667,218바이트는 기존 기준 자료로 따로 보존한다. R1 추가취득 180MiB 예산 해석은 decision 기록에 명시했다. 자동 redirect 수는 이전 handler가 노출하지 않아 HTTP 하위 요청 총수와 취득 호출 수를 동일시하지 않는다. 이 임무에서 429 또는 대기는 발생하지 않았다. 과거 429 기록은 역사적 증거로 남긴다.

## 메모리 제한 처리와 정의

`pet_batch_io.py`는 검증된 원자료를 새 로컬 SQLite 캐시로 스트리밍한다. 기존 캐시는 덮어쓰지 않는다. 전체 이벤트 키의 모든 변형을 하나의 UTC 날짜 묶음에 배치하여 날짜 경계 중복·상충을 분리하지 않는다. 객체는 `object_day`로 자르지 않고 참조 ID의 모든 변형을 보존한다. 신호는 모든 역할 시각과 ±0.5초 범위에 겹치는 구간을 취하며, 긴 구간·중복·겹침·잘못된 그룹/시각의 보수적 미확인 처리를 유지한다. 통계의 날짜/시간대는 Europe/Vienna를 별도로 사용한다.

원시 행 수와 고유 이벤트 수를 구분한다. 고유 이벤트는 유효 비음수·음수 검토·무효의 합이며, 음수를 0으로 바꾸거나 이상치를 임의 삭제하지 않는다. 짧은 PET 분모는 기록된 유효 비음수 상호작용이다. 신호조건 분모는 그중 두 역할 상태가 알려진 경우다. 전체 교통량·정지선 위반·사고확률의 분모가 아니다. 제공자 timestamp identity 대조는 자동 수치 검토이며 독립적인 기하학적 정확도 검증이 아니다.

다일자 bootstrap은 기존 고정 B=200, seed=20261012와 최소 7일/30건 조건을 유지한다. 날짜 클러스터는 관측된 교차로·기록일에 조건부인 탐색 구간이다. 임계값별 순위 범위는 일반 도시 위험 순위나 순위 신뢰구간이 아니다.

AI는 기존 6개 점유시간·객체 크기 특징만 사용하며 날짜×시나리오의 결정적 제한 표본에서 실행한다. PET·신호·ID를 학습 특징으로 쓰지 않는다. 날짜 분리, 양 역할 공유객체 격리, train-only 전처리·선택을 유지한다. 기존 누적 64회 실제 fit 예산을 초기화하지 않는다. 군집은 크기/이상치 분할일 수 있으며 탐색 분리나 ARI가 개선·정확도를 입증하지 않는다. 실제 선택 표본과 분할·fit 로그가 근거다.

## 제공자 신호 시각 표기 보완

첫 입력 probe에서 기존 정수 문자열 검사에 거부된 26행을 원표와 대조했다. 모두 `1.742945e+12` 같은 과학적 표기이며 Decimal로 정확히 해석한 값은 정수 밀리초이고 양의 구간을 이룬다. `timestamp_integer`는 부동소수점 반올림 없이 이 정수값만 허용한다. 분수·NaN·과대값과 ID 키의 과학적 표기는 여전히 거부한다. 26행을 삭제·보간하지 않았으며 원시 표기, 변환 정수값, 기존 10개 그룹 미확인 처리와 변경 근거는 `signal_timestamp_format_audit.json`에 남긴다. 제공자 표기의 유효숫자보다 세밀한 시각 정확도를 복원했다고 주장하지 않는다. 원시 정수 문자열만 허용한 기준과 수치 해석 기준의 차이는 데이터 형식 검토 결과이며 정확도 개선 실험이 아니다.

## 명령

새 프로젝트 폴더에 소스 ZIP을 풀고, 허가된 원자료를 profile의 경로와 SHA-256으로 준비한다. 기존 requirements.lock과 프로젝트 전용 가상환경을 사용한다. 전역 설치·권한 우회·외부 제출은 필요하지 않다.

```powershell
$env:PYTHONPATH='src'
$env:OMP_NUM_THREADS='1'
$env:OPENBLAS_NUM_THREADS='1'
$env:MKL_NUM_THREADS='1'
.\.venv\Scripts\python.exe tools/pet_bulk.py --profile configs/pet_multiday_finish.yaml --output runs/new_multiday_id
.\.venv\Scripts\python.exe tools/finish_evidence.py --pet-run runs/new_multiday_id --output runs/new_evidence_id
```

최신 소스 회귀와 실제 두 번 재현은 `tools/finish_verify.py --id <새_ID>`다. 이 명령은 유한한 로컬 테스트/분석 명령만 실행하며 Codex·SDK·에이전트나 `run_until_ready.py`를 호출하지 않는다. 이미 검증된 소스/입력이 바뀌지 않았다면 fit 예산을 소모해 반복 실행하지 않는다. 실패 결과와 실행 로그를 보존하고 새 이름을 사용한다.

최종 패키징은 `tools/finish_package.py --verification <검증_summary> --review <실제_별도검토_JSON> --run-id <새_ID>`다. 소스·입력·실행·결과 해시와 별도 검토의 미해결 차단 0건을 확인한다. 대용량 행별 산출물은 로컬 보존하고 경로·해시·생략 이유를 명시한다. 원자료 없는 ZIP만으로 실제 재실행이 가능하다고 주장하지 않는다.

## 변경 및 보존

기준 소스 커밋은 `def6f6c7a6ed4860a365ecf19174ce027a902e59`이며 기준 R1 인계는 `delivery/r1_pet_final_20261012_01`이다. 수정 이유는 전체 입력 경로 차이, 메모리 제한, 자동 사건 검토·AI 비교, 최신 소스 재현과 보고서 작성용 기술 근거 연결이다. 새 모듈과 새 출력 디렉터리를 추가하고 기존 원자료·완료 결과는 덮어쓰지 않는다. 요청 모델과 실제 런타임 확인 가능 범위는 이번 decision/별도 검토 기록에 남긴다. 런타임 ID 미노출을 실제 설정 검증 완료로 표기하지 않는다.
